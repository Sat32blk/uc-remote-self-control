Remote Self-Control Builder

Conditional buttons for the Remote Self-Control integration. Each button checks your devices or the remote, then runs the first branch that matches.

Log in

Enter the web-configurator PIN. Find it on the remote under Settings → Web configurator.

Backup, restore and removal

A backup holds everything you set up here: smart controls, quick menus and sliders, state icons and level pictures, ↩ buttons, start pages and Controls, plus the custom pictures they use. It doesn't hold the integration's login to the remote. Keep a copy before updating the integration or the remote.

Download backupSaves a .json file.

Restore

Remove everything (before uninstalling)

Puts back what the integration changed on your remote: state icons and level pictures go back to the buttons' own looks, ↩ buttons are taken off your pages and unmapped, page orders are restored (start pages off), borrowed volume keys and quick-menu buttons are given back. Your smart controls, sliders, quick menus and Controls stay defined. Download a backup first: restoring it puts everything back.

    Your smart controls and quick menus

    After saving a new control or menu, add it to the integration (Integrations → Remote Self-Control → add entities) and to the activities that use it. Smart controls are buttons; quick menus are lists that open a pop-up on a home tile or an activity page, and each choice runs its steps. Both run in the background, so they can't switch the remote's screen to another activity.

    Your state icons and sliders
    
    
    
    
    Your display sensors
    
    
    
    
    Each display is its own sensor of this integration, like each smart control is a button. After saving a new one, add it to the remote (Integrations → Remote Self-Control → add entities, or the Page Editor's "Not added yet"), then put it on a page with the Page Editor's sensor widget. It updates at once (no page rewrite). Smart controls can send it messages with the step Show on a display.
    
    
    
    
    
      How state icons, sliders and displays work
      
    Displays are sensors that show text: a default value (a device's volume, a slider, the time…) with text before and after it, that switches to something else for a while when a condition is met (a value changes, goes above or below a number, a Control is on, an activity starts), then goes back. They can also show messages one after another. The remote's font has most symbols and emoji, but not block characters, so bars are made of ◼◻, 🟩⬜ and the like.
    
      
    Sliders are light entities for a number on one of your devices, like the receiver's volume. Put one on a home page: tapping the tile opens the remote's slider pop-up. On a Remote 3 you can also assign it to an activity's touch slider. New sliders are in the Remote Sliders & Menus group when you add them to the integration.
    
      
    Pick a button on an activity page. Its current icon or text is the default look. Then drop an image (or type a label) for each state of a device, like ON or an input name. (Level graphics that follow a number are part of sliders: Create slider → Show the level on a page.) The button switches look within about 2 seconds of the change and goes back to its default when no state matches. What the button does when pressed doesn't change.
    
      
    Only activities with one page are offered: when a page of the activity on screen changes, the remote jumps back to that activity's first page, which would interrupt you on activities with more pages.

    Activities with a ↩ button
    
    
    
    
    

    
    Start pages
    
    
    Pick the page an activity opens on, depending on your devices: e.g. Watch TV opens on Apps if the Shield is on, otherwise on Live TV. To jump to a page while you're in an activity, use the Go to page step in a smart control or quick menu.
    
    
    
    
    
    
    
      How page jumps work
      
    The remote has no "go to page" command, but it always shows an activity's first page when it opens, and it jumps to the first page when the page order of the activity on screen changes. So the integration turns the page order around (keeping your swipe order, just starting at another page). When you leave the activity, your own order is put back, unless a start page picks another one. A jump takes about a second.
    
    
    
    
    
      How the ↩ button works
      
    The integration watches which activity you start (whether or not the old one turns off). In every activity listed here it keeps a ↩ button pointed at the activity you used before; pressing it opens that activity. The ↩ button can be on screen (text, back arrow or your own picture), on a physical button, or both.
    
      
    Turn off when leaving: when you switch from a marked activity to any other one, the integration sends the marked activity a plain "turn off" (within about 2 seconds). It's meant for a single device's control page.

    Controls
    
    
    
    
    
    
    
      How Controls work and what to set up on the remote
      
    This adds devices in the Remote Controls group: Control (a media player), Control Level (the same level as a light), Control Active (a sensor showing e.g. "Light · 60 %") and one Control: <name> switch per control. Add them to the integration and to your activities.
    
      
    Touch slider (Remote 3): set it once in the web configurator to Control (or Control Level). Volume rocker: with borrow on, nothing to set up; otherwise map Vol + / Vol − to Control's volume up / down yourself. The remote's own pop-ups show the level: the vertical one for the rocker, the horizontal one for the touch slider. Other buttons work too but get no pop-up.
    
      
    Turn a control on with its switch (put it on a page or map it to a button). Turning on another control switches straight to it. It turns off after the time set above without use, or stays on until you turn it off.
    
    
    
  
    

  
    
    
    
    
    A launcher is one button that opens the activity your conditions pick: e.g. if the Shield is on → Watch ShieldTV, otherwise → Watch RokuTV. Optionally it runs extra steps after that activity starts. Beta: it creates activities on your remote; make a backup in the web configurator first.
    
    
    
    
    
    
      
    
      
      How launchers work
      
      The remote only switches to an activity's screen when the button you press starts that activity directly; a macro or an integration can start it, but the screen stays where it is. So the launcher decides before you press: for each activity of a launcher the integration keeps a launcher copy of that activity (same devices, pages and buttons, named after the launcher), with any extra steps added at the end of its start sequence. The launcher's buttons start one of the copies, and are re-pointed whenever your conditions pick another one. Pressing the button is then a plain "start activity", so the screen opens.
      
      
      Already on or all off: the remote decides that, as for any activity. When a copy starts it skips the power-on steps of devices that are already on, then runs the rest of the start sequence (inputs and the like) and the extra steps. Pressing the button while that copy is already open runs its start sequence again in the same way.
      
      
      Edit the original activity, not the copy: the copies follow their original within about a minute (pages, buttons, devices and the start sequence). ↩, start pages, state icons and Controls treat a copy as its original. The copies are in the same activity groups as their original, so switching between them doesn't turn devices off and on.
      
      
      Buttons: add one here (page button, physical button or home screen), or in the web configurator pick one of the launcher's copies as the activity to start; the integration finds those and keeps them pointed right. A button on a page of the activity on screen is re-pointed when you leave that activity (changing a page you're looking at would jump to page 1). Physical buttons and home tiles change at once.
